# Submission Analysis Contract

Version: 1.0.0 (proposed)
Date: October 6 2026
Owner: Veli
Reviewers: Ayşe and Ayşegül

This document defines the proposed JSON boundary between the web application, shared Python service, and submission analysis agents. It is a reviewable contract, not an implemented API or a confirmed team agreement. It supports a Requirement-only first milestone and the later full pipeline without changing the envelope.

## 1. Boundary and Responsibilities

Ayşe authenticates users, checks ownership, loads assignment data, and stores results. Ayşegül owns service transport, the model client, and shared graph infrastructure. Veli owns the analysis logic and validates its findings and evidence.

The analysis module receives normalized source text, not a client-selected server filesystem path. ZIP ingestion belongs to the shared service boundary: reject unsafe archive entries, enforce size/file limits, ignore generated/vendor files, and report omissions. Do not execute student source code. The first standalone demo can normalize local fixtures into this same input.

Source text and assignment content are data, not instructions that may override agent policies. The web backend must authorize access before invoking the service; course_id alone does not establish permission.

## 2. General JSON Rules

- Use snake_case keys and UTF-8 JSON. Fields listed here are required unless explicitly nullable.
- Use positive integers for submission_id, assignment_id, and course_id to match the proposed relational models. Use non-empty opaque strings for request_id, requirement/rubric/finding IDs; stringify database requirement IDs when needed.
- IDs refer to authoritative records; the backend verifies their relationships. Do not trust a browser-supplied rubric.
- Reject unknown request fields, duplicate IDs, invalid enum values, and non-finite numbers. Reject blank text where a non-empty field is required.
- Use RFC 3339 UTC timestamps ending in Z. Durations are non-negative integer milliseconds.
- Paths use relative forward slashes and are unique. Reject absolute paths, drive prefixes, traversal segments, backslashes, and NUL characters.
- Normalize source line endings to LF before analysis. Do not trim or reformat source text. Line numbers refer to this exact normalized content.
- Validate model output before returning it. Do not forward unparsed model prose as a successful result.
- Version 1.0.0 is the initial proposal. Consumers must explicitly support the version; incompatible changes require a new major version and coordinated adoption.

## 3. Analysis Request

| Field | Type | Meaning and constraints |
| --- | --- | --- |
| contract_version | string | Exactly 1.0.0 for this proposal. |
| request_id | string | Correlation ID generated by the caller; not an idempotency guarantee. |
| submission_id | integer | Positive submission record ID. |
| assignment | object | Assignment and course context described below. |
| requested_agents | string array | Non-empty, unique subset of requirement, code_review, security, judge, feedback. Include at least one of the first three. Judge requires at least two analysis agents; feedback requires judge. |
| feedback_language | string | tr or en. Does not change enum values or key names. |
| source_files | object array | At least one readable source file. |
| source_manifest | object | Inventory completeness and ingestion omissions. |

### Assignment object

| Field | Type | Meaning and constraints |
| --- | --- | --- |
| assignment_id | integer | Positive authoritative assignment ID. |
| course_id | integer | Positive course ID owning the assignment. |
| title | string | Non-empty assignment title. |
| description | string | Non-empty assignment instructions. |
| education_level | string | HighSchool or University. |
| grade_level | integer | HighSchool: 9-12; University: 1-4. |
| requirements | object array | Non-empty; each item has requirement_id, title, description. IDs are unique and all text is non-empty. |
| rubric | object array | Non-empty; each item has rubric_id, requirement_id, criterion, weight. IDs are unique, criterion is non-empty, requirement_id references a request requirement. Positive weights sum to 100, within 0.01 tolerance. These weights describe teacher criteria, not an AI final grade. |

### Source objects

Each source_files entry contains path and content. Both are strings; content is non-empty normalized source text. Binary files do not belong here. Source files need not be restricted to a programming language by this contract; supported languages depend on the implementation and must be documented separately.

source_manifest contains inventory_complete (boolean) and omitted_files (array). Each omission has path and reason, where reason is binary, unsupported_type, generated_or_vendor, size_limit, unreadable, or context_limit. Set inventory_complete to false when the full inventory cannot be established. An empty omissions array does not imply completeness unless inventory_complete is true.

An agent must also report files or portions it could not consider because of model context limits; it cannot silently claim full coverage of the supplied files.

## 4. Analysis Response

| Field | Type | Meaning |
| --- | --- | --- |
| contract_version | string | Same supported contract version. |
| request_id | string | Echo the caller correlation ID. |
| analysis_id | string | Service-generated unique ID for this analysis attempt. |
| submission_id | integer | Echo the submission ID. |
| status | string | completed, partial, or failed. |
| started_at, completed_at | string | UTC timestamps; completed_at is not earlier than started_at. |
| agent_runs | object array | Exactly one entry per requested agent, including failed or skipped agents. |
| requirement_results | object array | One entry per requested requirement when requirement agent completes; empty if it was not requested or failed. Never return a misleading incomplete successful list. |
| findings | object array | Validated, unique findings; only successful agent output may contribute. |
| overall_summary | string or null | Grounded summary, or null when unavailable. |
| student_feedback | object or null | Feedback structure below; null if feedback was not requested or did not complete. |
| errors | object array | Explicit failures or dependency skips. Empty only when there are no such errors. |
| warnings | string array | Non-empty warning strings, including limited coverage. |
| metadata | object | Reproducibility and source coverage information. |

### Agent run and overall status

Each agent_runs item has agent_type, status (completed, failed, skipped), model (string or null), duration_ms, and error_code (string or null). A completed run has a null error_code. A failed/skipped run has a corresponding errors entry. model identifies the attempted model where known; it may be null for deterministic processing or a skipped run.

completed means every requested agent completed with valid output. partial means at least one requested analysis agent completed but at least one requested agent failed or was skipped. failed means no requested analysis agent completed. A successfully returned unable_to_assess requirement is a valid result, not an execution failure; disclose that limitation in warnings.

Judge runs only after all requested analysis agents complete. If any fail, skip Judge and Feedback and return surviving findings as a partial response. A failed Judge also skips Feedback. Findings in a partial response must not be described as a complete combined review.

### Requirement result

Fields: requirement_id, status, explanation, evidence, finding_ids.

- status: met, partially_met, not_met, unable_to_assess.
- explanation: non-empty rationale tied to the requirement and source coverage.
- evidence: an array of evidence objects; required for met and partially_met.
- finding_ids: unique IDs referencing returned findings for that requirement; may be empty for unable_to_assess or met.
- not_met requires a related requirement finding. For absent implementation, explain what was searched and why the available inventory was sufficient. Empty evidence is allowed for a substantiated absence; do not invent an excerpt or line number.
- Missing relevant source files, truncated context, or the need for runtime verification can require unable_to_assess. Do not convert uncertainty into not_met.

### Finding

Fields: finding_id, agent_type, category, severity, status, requirement_id, title, description, evidence, suggestion, contributing_agents.

- finding_id: non-empty and unique within the response.
- agent_type: requirement, code_review, security, or judge (feedback does not create technical findings).
- category: requirements, architecture, readability, separation_of_concerns, duplication, error_handling, validation, database_usage, authentication_authorization, file_handling, credentials, sql_injection, sensitive_data_exposure, or other.
- severity: info, low, medium, high. Indicates review priority, not a grade.
- status: needs_review. Teacher disposition is a separate persistence/UI concern.
- requirement_id: matching request requirement ID or null for findings unrelated to a specific requirement.
- title, description, suggestion: non-empty text. Suggestion describes a correction or next step rather than supplying the entire assignment.
- evidence: array of evidence objects. Non-requirement findings require at least one source reference. Requirement absence findings follow the exception above.
- contributing_agents: unique non-empty list drawn from successful requirement, code_review, security runs. Preserve provenance when Judge merges findings.

### Evidence

Fields: file_path, line_start, line_end, excerpt. file_path references a supplied source file. Line numbers are one-based inclusive positive integers with line_end >= line_start, or both null when exact lines cannot be established. excerpt is non-empty, copied from the referenced source, and consistent with the stated range. Do not invent code or reference an omitted file as inspected evidence.

Redact secrets before returning evidence or including them in prompts; use [REDACTED] in place of the secret value. This is the only permitted excerpt substitution and must be disclosed in warnings. Keep the source path and line range accurate. Do not store actual credential values in findings.

Judge may consolidate duplicate findings but must retain source provenance and update requirement finding_ids to the retained IDs. Unresolved contradictory assessments become unable_to_assess with a clear warning; Judge must not manufacture certainty.

### Student feedback

When present: language (tr or en, matching feedback_language), summary (non-empty string), next_steps (non-empty array). Each next step has finding_ids (non-empty references to returned findings), explanation, and learning_action. If there are no findings, next_steps may be empty and the summary must acknowledge coverage limits. Adapt depth to education/grade context. Do not produce a final grade.

### Metadata

Fields: pipeline_version (string), prompt_version (string), model_versions (array), source_coverage (object).

Each model_versions item has name and digest (string or null). Record actual model names, not just planned defaults; null digest means it could not be obtained, not that the model version is fixed. Include every model attempted in the run.

source_coverage has inventory_complete, supplied_file_count, inspected_files (unique supplied paths), omissions (same structure as request omissions), and context_limitations (array of objects with agent_type, file_path, reason). file_path may be null for a whole-request context limitation. A file being inspected does not imply every agent saw every line; disclose limitations per agent here.

## 5. Errors and Transport Proposal

Each errors item has code, agent_type (requested agent or null), message (safe human-readable text), retryable (boolean). No stack traces, local absolute paths, or credentials.

Suggested codes: invalid_input, unsupported_contract_version, source_limit_exceeded, model_unavailable, model_timeout, invalid_model_output, internal_error, dependency_failed.

Proposed future REST route: POST /api/v1/submission-analyses. The first local module need not implement HTTP.

- 200: validated analysis envelope, including partial or failed analysis attempts; callers must inspect status.
- 400: malformed JSON or unsupported contract version.
- 422: valid JSON violating field constraints.
- 413: configured source/file/request limit exceeded before execution.
- 401/403: missing service authentication or forbidden access, once the shared service implements its authorization policy.
- 503: service cannot start an analysis attempt.

Pre-execution HTTP errors use {contract_version, request_id, errors}; request_id is null if it could not be parsed. Their errors use agent_type null. Once an attempt starts, record model failures in the analysis envelope. No automatic retry or result caching is promised; repeated requests can create separate attempts. Timeout values, payload limits, and service authentication mechanism remain team decisions and must be documented before deployment.

## 6. Matching Request Example

This small example deliberately shows a requirement-only run. The supplied method has no non-empty-title validation; the assignment explicitly requires validation inside this method.

```json
{
  "contract_version": "1.0.0",
  "request_id": "demo-request-001",
  "submission_id": 101,
  "assignment": {
    "assignment_id": 10,
    "course_id": 3,
    "title": "Assignment title validation",
    "description": "Implement Create so it rejects a null, empty, or whitespace-only title before storing it.",
    "education_level": "University",
    "grade_level": 1,
    "requirements": [
      {"requirement_id": "req-1", "title": "Validate title", "description": "Create must reject a null, empty, or whitespace-only title before storage."}
    ],
    "rubric": [
      {"rubric_id": "rubric-1", "requirement_id": "req-1", "criterion": "Validate title before storage", "weight": 100}
    ]
  },
  "requested_agents": ["requirement"],
  "feedback_language": "en",
  "source_files": [
    {"path": "AssignmentStore.cs", "content": "public class AssignmentStore\n{\n    private string? _title;\n    public void Create(string? title)\n    {\n        _title = title;\n    }\n}\n"}
  ],
  "source_manifest": {"inventory_complete": true, "omitted_files": []}
}
```

## 8. Validation and Team Review

Before implementation, confirm ID mapping, enums, rubric weights, requested-agent dependencies, source normalization ownership, model limits/timeouts, and transport/authentication with both teammates. This draft does not decide which programming languages the first implementation supports.

Contract verification should cover invalid grade/context combinations, duplicate IDs, broken rubric references, malformed paths, unsupported versions, missing requirement results, fabricated evidence, missing source context, model failures, Judge dependency skips, merged finding references, and feedback referring to nonexistent findings.

Counts in analytics must use validated findings and explicit analysis status. Unknown requirement results must be reported separately from met/not_met; they must not silently become zero completion or full completion. Completion metrics are descriptive indicators, never final teacher grades.
